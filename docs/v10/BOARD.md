## Status format (normalized for `scripts/v10-pulse.sh`)

Every row's `Status` cell is exactly one token, an `@`, and a UTC timestamp
(`<token>@YYYY-MM-DDTHH:MMZ`) -- the time the status last changed. Prose,
history, and caveats move to `Notes`; `Status` itself must stay
machine-parseable with no free text. Tokens, in the lifecycle order the pulse
script expects:

`ready` -> `building` -> `review` -> `review-blocked` (returns to `building`)
-> `approved` -> `merged` -> `released`. Side states: `blocked` (needs a
Captain/PO decision), `rejected` (sent back, will be re-cut), `parked`
(deliberately shelved).

`merged` here means "the Captain landed it on main" -- a slice sits at
`merged` until the Captain flips it to `released` on the next version bump
that ships it. The pulse script does NOT trust this field for its own
"merged-but-unreleased age" computation: it derives that directly from git
(`git log` on main after the last release tag) since a table cell can go
stale between edits. This field still matters for humans and for the
ready/building/review/blocked counts, which git cannot derive.
